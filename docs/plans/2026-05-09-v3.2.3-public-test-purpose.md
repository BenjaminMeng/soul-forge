# Soul Forge v3.2.3 Public Test Purpose

**Date:** 2026-05-09  
**Target repo:** `BenjaminMeng/soul-forge` public repository  
**Base version:** v3.2.2  
**Target version:** v3.2.3  
**Status:** Purpose and release boundary document

## 1. Why This Version Exists

v3.2.3 exists to make the current public Soul Forge release usable for a small friend test group with minimal risk.

The goal is not to publish the newest internal Soul Forge work. The internal repository has newer P1-B/P1-C research and runtime experiments, but those are outside this release. For this test, stability matters more than capability.

This version should remain close to the existing public v3.2.2 codebase and only reduce practical friction for early testers.

## 2. Real Test Context

The expected use case is:

- The maintainer creates or prepares an OpenClaw agent.
- Soul Forge is preinstalled or installed as part of that setup.
- A friend uses the agent through the configured chat channel.
- The friend starts Soul Forge calibration and reports whether the experience is usable.

The tester is not expected to understand Soul Forge internals, install experimental features, or debug OpenClaw configuration.

## 3. Release Principle

Use the smallest patch that makes public v3.2.2 safer to test.

Do not convert this release into a productization pass. Do not sync the internal repository wholesale. Do not add new architecture unless a current public-version blocker proves it is necessary.

## 4. In Scope

The v3.2.3 patch may include:

- Version metadata consistency across `version.json`, `package.json`, README, changelog, and handler constant.
- Installer reliability checks for the current public package.
- Small installer fixes if verification shows current v3.2.2 install is fragile.
- Clear public test instructions in README.
- Confirmation that `hooks.internal.enabled` is enabled during install.
- Confirmation that existing user files are backed up and not overwritten unexpectedly.
- Confirmation that repeated install is idempotent.
- Confirmation that required files are installed to the expected OpenClaw locations.
- A concise changelog entry explaining this is a public stability test build.

## 5. Out of Scope

The v3.2.3 patch must not include:

- P1-B.3 limited-active runtime tuning.
- P1-C Dream, windowing, candidates, or distillation.
- Internal real-world smoke evidence.
- Temporary evidence directories such as `.tmp-*`.
- `node_modules`.
- Broad documentation rewrite.
- WeChat-specific architecture changes.
- Preinstall/headless installer redesign unless public v3.2.2 cannot support the test without it.
- Public package export from the current internal dirty worktree.

## 6. Version Boundary

v3.2.3 should be treated as a public stability patch over v3.2.2.

It should not claim to contain v3.4 or v3.5 internal features.

Expected version updates:

```text
version.json                         -> 3.2.3
package.json                         -> 3.2.3 if currently stale
README badge                         -> 3.2.3
hooks/soul-forge-bootstrap/handler.js -> SOUL_FORGE_VERSION = 3.2.3
CHANGELOG.md                         -> add v3.2.3 entry
```

## 7. Tester-Facing Promise

For this release, the promise to testers is:

```text
Soul Forge should install cleanly, start calibration, preserve existing files,
and provide a usable stable public experience.
```

The release does not promise:

```text
latest internal learning features,
Dream or distillation,
advanced runtime tuning,
or long-horizon adaptation quality.
```

## 8. Minimal Acceptance Criteria

Before v3.2.3 is pushed to the public repository, verify:

1. Public repo worktree is clean before the patch starts.
2. Version metadata is consistent.
3. `node --check installer.js` passes.
4. `node --check hooks/soul-forge-bootstrap/handler.js` passes.
5. Fresh install succeeds in a sandbox OpenClaw home.
6. Repeated install does not overwrite existing `config.json`, `memory.md`, or user personality files.
7. Installer enables `hooks.internal.enabled`.
8. Required files are present after install:
   - `skills/soul-forge/SKILL.md`
   - `hooks/soul-forge-bootstrap/HOOK.md`
   - `hooks/soul-forge-bootstrap/handler.js`
   - `workspace/.soul_forge/config.json`
   - `workspace/.soul_forge/memory.md`
   - `workspace/.soul_forge/insights.md`
   - `workspace/.soul_history/SOUL_INIT.md`
   - `workspace/.soul_history/IDENTITY_INIT.md`
9. README tells testers how to start the test without suggesting internal-only features.
10. Changelog explains that v3.2.3 is a small public stability test patch.

## 9. Recommended Patch Shape

Keep the patch small. Expected files:

```text
version.json
package.json
README.md
CHANGELOG.md
hooks/soul-forge-bootstrap/handler.js
installer.js, only if verification exposes an install issue
```

If the patch grows beyond this list, re-check whether the change belongs in this release.

## 10. Decision Record

The maintainer intentionally chose not to publish the newest internal Soul Forge version for this test.

Reason:

- The public v3.2.2 line is smaller and more stable.
- The test group needs a usable version, not a feature-complete experimental one.
- Internal P1-B/P1-C work can continue separately without increasing public test risk.

This document exists so future release work does not accidentally turn v3.2.3 into a broad internal sync.
